# Fork rules (DXT2000/garmin_mcp)

The root `CLAUDE.md` is upstream's file and is left as upstream wrote it, so upstream syncs do not
conflict on it. This file holds only what the fork adds; where the two disagree, this file wins.

## This is a fork

`DXT2000/garmin_mcp` is a **public** fork of `Taxuspt/garmin_mcp` (`upstream` remote).

- **Never put the maintainer's own Garmin data in anything pushed**: commits, PR text, docstrings,
  comments, fixtures, `FORK_ROADMAP.md`. That covers fitness and health numbers, race names and
  dates, place and activity names, gear models, and account/activity/event IDs. Describe live
  checks generically ("checked live against a real account: create, update, delete; nothing left
  over"), use invented values in fixtures, and grep the diff and message for real values from the
  session before pushing.
- Parked work and fork decisions live in [FORK_ROADMAP.md](../FORK_ROADMAP.md): issues are off on
  this fork, and `.gitignore` excludes `docs/*`, so a file under `docs/` is never committed.
- `gh pr create` in a fork targets upstream by default: always pass `--repo DXT2000/garmin_mcp`.
- Sync upstream with a real merge (branch off `main`, `git merge upstream/main`, PR merged with
  `--merge`). Never squash or rebase a sync: it drops upstream ancestry and the next sync
  re-conflicts. On conflicts, follow FORK_ROADMAP "Keep the fork's side when syncing upstream".
- Fork fixes are not sent upstream unless the maintainer says so.

## Commands

- `dxt/manifest.json` is generated by `scripts/generate_dxt_tools.py`; `tests/unit/test_dxt_manifest.py`
  fails when it is stale.
- After bumping a dependency, refresh `uv.lock` (`uv lock --upgrade`): `uvx --from git+...` installs
  ignore the lock, so a stale lock means tests run older packages than real installs.

## Working on tools

- Mocked tests cannot see Garmin-side behaviour. Check a write path live (with the maintainer's OK)
  and, for workouts, decode the FIT Garmin generates
  (`/workout-service/workout/FIT/{id}`): an API read-back looks right even when the workout is
  broken. Example: absolute cycling watts are target type 2 `power.zone`, never 6 (that is
  `pace.zone` and turns watts into speed); the fork refuses the wrong form.
